# Roadmap & Status

This file tracks what is already done in the **Destroy Windows 11 Revival** port
and what is still left to do. It is meant to be kept up to date as work lands.

## Current status

The core port from the original `Destroy-Windows-10-Spying` to a Windows 11-aware
build is **done**, **compiles clean** (0 errors, 0 warnings) and is committed on the
`win11` branch.

---

## Done

### Port & Windows 11 support

- **Windows 11 detection** (build `>= 22000`) with a tri-state split: Windows 7/8.1,
  Windows 10 and Windows 11 each get their own settings panel. Detection reads
  `CurrentBuildNumber` (the `ProductName` registry string still reports "Windows 10"
  on some Windows 11 builds, so it cannot be trusted).
- **App removal rewritten to use exact package names** (`DWS/lib/Win11Apps.cs`),
  removing for all users and deleting provisioned copies. No more wildcards that
  could also match Notepad/Sticky Notes.
- **New Windows 11 app groups** (Copilot/AI Hub, Teams, new Outlook, Clipchamp,
  Widgets, PC Manager/misc) with checkboxes and `Professional Mode` gating.
- **Windows 11 registry tweaks** (`ApplyWin11Tweaks()`): Copilot, Recall/AI,
  Widgets, Start/Explorer ads, Bing/Cortana, AI-service manual start, auto
  device-encryption prevention. Every value was verified line-by-line against the
  Win11Debloat regfiles and the shipped ADMX templates on a real Windows 11 26H2
  (build 26300) system.
- **Telemetry services disabled (not deleted) by default**; deletion is an opt-in
  expert option.
- **Hosts-only blocking.** The Windows Firewall is never touched; the old `netsh`
  rules for `explorer.exe`/`WSearch` (which broke Store, Update and Explorer) were
  removed. The 2015 IP-blackhole list is expert-mode only.
- **Removed the insecure HTTP in-app auto-update.**
- **Branding** updated to "Destroy Windows 11 Spying" / DWS 11 (assembly info,
  manifest with `supportedOS` entries for Win7/8/8.1/10/11).

### Windows 11 visual refresh

- [x] **Rounded window corners** via `DwmSetWindowAttribute` /
      `DWMWA_WINDOW_CORNER_PREFERENCE` (`DWS/lib/Win11Visual.cs`), applied only on
      build `>= 22000`.
- [x] **Dark or light title bar** matching the active palette via
      `DWMWA_USE_IMMERSIVE_DARK_MODE`.
- [x] **Full Windows 11 light/dark palette** applied recursively over the control
      tree (`Win11Visual.ApplyPalette`): surfaces, text, accent buttons, fields,
      tab pages. Custom-painted chrome (title bar, border panels, close button)
      keeps its own colours.
- [x] **Modern typography** — `Segoe UI Variable Text` when present, `Segoe UI`
      otherwise (`Win11Visual.ModernFontFamily`).
- [x] **Dark-mode toggle** (`checkBoxWin11DarkMode`) in the Utilities tab, visible
      and enabled on Windows 11 only; hidden on Windows 10 / 7 / 8.1.
- [x] The old animated **rainbow 1px border** is replaced by the native Window
      chrome on Windows 11 (the square picture-box borders clash with rounded
      corners) and is untouched on older systems.
- [x] Windows 10 / 7 / 8.1 keep the original look exactly — nothing is applied
      there.

### Icon

- [x] New multi-resolution `DWS/icon.ico` (16, 24, 32, 48, 64, 128, 256 px; rounded
      blue gradient, white shield, "11" glyph) — generated by
      `tools/gen-icon.ps1`, verified by pixel sampling, and wired into
      `DWS_Lite.csproj`. The old `other_cat.ico` was removed.

### Registry backup & restore

- [x] **`DWS/lib/RegistryBackup.cs`** snapshots all **55 registry values** DWS writes
      (extracted straight out of the `SetRegValue*` call sites so the list cannot
      drift) into a timestamped folder, plus plain `.reg` exports of the affected
      parent keys for manual inspection.
- [x] Backups are created **automatically before every run**, and on demand from
      *Backup registry now*.
- [x] *Restore registry backup...* reverses a backup exactly: values that existed are
      put back, values that did **not** exist are deleted again. Restore is
      per-entry fault tolerant — one inaccessible key never aborts the whole restore.
- [x] Verified against the live registry: 38 of 55 values present on the test
      machine, manifest round-trips correctly, and the restore correctly reported
      "17 restored / 29 skipped (access denied)" under a non-elevated session.

### Build & release pipeline

- [x] **The project compiles.** Fixed with .NET SDK 8 + the
      `Microsoft.NETFramework.ReferenceAssemblies.net40` NuGet package. This also
      removed the `MSB3644` "reference assemblies for v4.0 not found" failure.
- [x] **Every legacy `CS0168` unused-variable warning cleaned** — 10 `#if DEBUG`
      fences around `catch (Exception ex)` were unwrapped so exception messages are
      now logged in Release too.
- [x] **`.resx` files no longer carry binary data.** The old `Color1` / `Bitmap1` /
      `Icon1` template leftovers were removed from all 20 `.resx` files, and the
      image entries were moved from `ResXFileRef` blobs to real embedded files
      (`DWS\Resources\*.png`). This is what let a .NET 4.0 project survive the modern
      resource compiler, which insists on `System.Resources.Extensions` (4.6.2+ only)
      for non-string resources.
- [x] **GitHub Actions CI** (`.github/workflows/build.yml`) builds the `win11` branch
      on `windows-latest`, checks the binary was produced and uploads it as an
      artifact.
- [x] **`build.cmd`** one-step local build; documented in the README.
- [x] `.gitignore` confirmed to cover `bin/`, `obj/`, `*.pdb`, `*.log`.

### Translations

- [x] The 12 new Windows 11 / backup strings are now translated in **all 17 language
      files** (was en-US + es-ES only). The pre-existing
      `GetTranslateText()` fallback to en-US is still in place as a safety net.
